# Морской бой на C# — пошаговый план разработки

Формат: 13 спринтов, от пустого консольного проекта до игры с ИИ.
Каждый спринт — рабочая версия программы. Не переходить дальше, пока текущий спринт не пройден по критериям приёмки.

---

## Спринт 0. Настройка проекта

**Цель:** создать проект, который компилируется и запускается.

**Задачи:**
- [ ] Создать консольный проект (`dotnet new console -n Battleship`)
- [ ] Убедиться, что `dotnet run` работает и печатает "Hello World"
- [ ] Создать структуру папок: `Models/`, `Core/` (для будущих классов)
- [ ] Настроить git-репозиторий (опционально, но полезно для привычки)

**Definition of Done:** проект запускается без ошибок, есть пустая заготовка `Program.cs`.

## Спринт 1. Пустое поле

**Цель:** напечатать в консоли поле 10×10.

**Задачи:**
- [ ] Создать `char[,] grid = new char[10, 10]`, заполнить символом `.`
- [ ] Написать метод `PrintGrid(char[,] grid)` — вывод построчно
- [ ] Добавить подписи столбцов (1–10) сверху и строк (A–J) слева
- [ ] Выровнять вывод пробелами, чтобы сетка не "съезжала"

**Классы/методы:**
- Пока можно писать всё в `Program.cs` — рефакторинг в классы будет позже, это нормально

**Definition of Done:** при запуске видно аккуратное поле 10×10 с подписями по краям.

**Частые ошибки:** индексы массива путают со строками/столбцами; забывают, что `grid[row, col]`, а не `grid[x, y]`.

## Спринт 2. Класс `Ship`

**Цель:** описать корабль как объект, а не набор чисел.

**Задачи:**
- [ ] Создать `Models/Ship.cs`
- [ ] Поля: `string Name`, `int Size`, `List<(int Row, int Col)> Cells`
- [ ] Конструктор: принимает стартовую клетку, размер, направление (`bool horizontal`) — сам вычисляет все `Cells`
- [ ] Метод `bool OccupiesCell(int row, int col)`

**Definition of Done:** можно создать `new Ship("Эсминец", 4, startRow: 0, startCol: 0, horizontal: true)` и получить список из 4 клеток.

**Проверка (unit-тест вручную в Main):** вывести `ship.Cells` в консоль и убедиться, что координаты верные для горизонтали и вертикали.

---

## Спринт 3. Класс `Board`, один захардкоженный корабль

**Цель:** объединить поле и корабль в один объект.

**Задачи:**
- [ ] Создать `Core/Board.cs`
- [ ] Поля: `char[,] Grid`, `List<Ship> Ships`
- [ ] Метод `void PlaceShipDirectly(Ship ship)` — без проверок, просто добавляет в `Ships` и рисует `S` на `Grid`
- [ ] Метод `void Print()` — переносим логику вывода из Спринта 1 сюда
- [ ] В `Main` создать `Board`, разместить 1 корабль вручную (жёсткие координаты), напечатать

**Definition of Done:** поле выводится через `board.Print()`, корабль виден на поле.

---

## Спринт 4. Несколько кораблей

**Цель:** разместить весь стандартный флот (без проверок пересечений).

**Задачи:**
- [ ] В `Main` (или отдельном методе `SetupFleet()`) создать список из 10 кораблей:
  - 1× четырёхпалубный
  - 2× трёхпалубный
  - 3× двухпалубный
  - 4× однопалубный
- [ ] Разместить их на разных захардкоженных координатах
- [ ] Убедиться, что все видны на поле одновременно

**Definition of Done:** поле показывает 10 кораблей, они не накладываются друг на друга (пока проверяется вручную, глазами).

---

## Спринт 5. Стрельба (без логики попадания)

**Цель:** научиться менять состояние клетки по вводу пользователя.

**Задачи:**
- [ ] Считать с консоли два числа: `row`, `col` (например `Console.ReadLine().Split(' ')`)
- [ ] Написать метод `Board.MarkShot(int row, int col)` — просто ставит `X` в `Grid`
- [ ] Обернуть в `while(true)`, чтобы можно было стрелять несколько раз подряд
- [ ] После каждого выстрела — печатать обновлённое поле

**Definition of Done:** вводишь координаты — на поле появляется `X`, поле перерисовывается.

**Подсказка:** пока не проверяем, что ввели корректные числа — это будет в Спринте 9.

---

## Спринт 6. Попадание и промах

**Цель:** отличать выстрел по кораблю от выстрела в пустоту.

**Задачи:**
- [ ] Метод `Board.ReceiveShot(int row, int col)`, возвращает `enum ShotResult { Miss, Hit, AlreadyShot }`
- [ ] Внутри — проверка: есть ли в `Ships` корабль с `OccupiesCell(row, col) == true`
- [ ] Если да — отметить клетку как `H` (Hit), в консоль вывести "Попадание!"
- [ ] Если нет — отметить как `M` (Miss), вывести "Промах"
- [ ] Если клетка уже была отмечена ранее — вернуть `AlreadyShot`, не тратить ход

**Definition of Done:** стрельба по кораблю и по пустой клетке даёт разные сообщения и разные символы на поле.

---

## Спринт 7. Потопление корабля

**Цель:** корабль должен "знать", жив он или потоплен.

**Задачи:**
- [ ] В `Ship` добавить `List<(int, int)> HitCells`
- [ ] Метод `void RegisterHit(int row, int col)` — добавляет клетку в `HitCells`
- [ ] Метод `bool IsSunk()` — сравнивает количество `HitCells` с `Cells`
- [ ] В `Board.ReceiveShot` — при попадании находить нужный `Ship`, вызывать `RegisterHit`, проверять `IsSunk()`
- [ ] Добавить `ShotResult.Sunk`, выводить "Корабль потоплен!"

**Definition of Done:** после того как подбиты все клетки одного корабля, программа явно сообщает о потоплении (а не просто "попадание").

---

## Спринт 8. Условие победы и игровой цикл

**Цель:** игра должна заканчиваться.

**Задачи:**
- [ ] Метод `Board.AllShipsSunk()` — проверяет `IsSunk()` для всех кораблей в списке
- [ ] Обернуть стрельбу в `while (!board.AllShipsSunk())`
- [ ] При победе — вывести "Поздравляем, вы потопили весь флот!" и завершить программу
- [ ] Добавить счётчик ходов, вывести в конце "Вы справились за N ходов"

**Definition of Done:** играется от начала до конца одним игроком против захардкоженного флота, с явным финалом.

**Это контрольная точка №1** — рабочая мини-игра "соло против расставленного поля". Хороший момент показать/протестировать целиком.

---

## Спринт 9. Парсинг координат в формате "B7"

**Цель:** удобный ввод вместо "3 4".

**Задачи:**
- [ ] Написать `bool TryParseCoordinate(string input, out int row, out int col)`
- [ ] Разбор: первая буква → row (A=0, B=1, ...), остальное → число → col (1=0, 2=1, ...)
- [ ] Обработка ошибок: пустая строка, буква вне диапазона A-J, число вне диапазона 1-10, отсутствие числа после буквы
- [ ] Заменить старый ввод "row col" на новый формат в игровом цикле
- [ ] При некорректном вводе — не тратить ход, просить ввести заново

**Definition of Done:** ввод "B7", "b7", "K11", "abc" — все обрабатываются корректно (первые два — как валидные, остальные — с понятным сообщением об ошибке).

---

## Спринт 10. Расстановка кораблей вручную (проверка правил)

**Цель:** игрок сам расставляет флот, с проверкой корректности.

**Задачи:**
- [ ] Метод `bool Board.CanPlaceShip(Ship ship)` — проверяет:
  - все клетки в границах 0–9
  - ни одна клетка не занята другим кораблём
  - ни одна клетка не соприкасается (включая диагонали) с другим кораблём
- [ ] Метод `bool Board.PlaceShip(Ship ship)` — вызывает `CanPlaceShip`, если true — добавляет корабль и нарисует его, иначе возвращает false
- [ ] Метод `SetupFleetInteractive()` — для каждого корабля из стандартного набора: спросить координату старта + направление, вызвать `PlaceShip`, при неудаче — повторить ввод
- [ ] После каждого успешного размещения — печатать текущее поле (чтобы видеть прогресс)

**Definition of Done:** игрок может расставить весь флот вручную, программа не даёт поставить корабли внахлёст или впритык.

---

## Спринт 11. Автоматическая (случайная) расстановка

**Цель:** генерировать флот программно — нужно и для быстрого старта, и позже для компьютерного соперника.

**Задачи:**
- [ ] Метод `Board.PlaceFleetRandomly(List<Ship> fleet)`
- [ ] Для каждого корабля: цикл до 100 попыток — случайные `row`, `col`, `horizontal`, попытка `PlaceShip`
- [ ] Если за 100 попыток не получилось — выбросить исключение или пересоздать поле с нуля (для новичка проще: просто перезапустить всю расстановку)
- [ ] В `Main` дать выбор: расставить вручную или случайно (`Console.ReadLine()` — "1" или "2")

**Definition of Done:** можно сгенерировать корректно расставленный флот одной командой, без единого пересечения или касания кораблей.

**Это контрольная точка №2** — расстановка полностью готова, можно двигаться к двум игрокам.

---

## Спринт 12. Два игрока за одной клавиатурой (hot-seat)

**Цель:** подготовка к архитектуре "игрок делает ход", независимо от того, кто за ним стоит.

**Задачи:**
- [ ] Создать базовый класс `Player`:
  - `string Name`
  - `Board OwnBoard`
  - `virtual (int row, int col) GetShot()` — виртуальный метод хода
- [ ] Создать `HumanPlayer : Player` — переопределяет `GetShot()`, спрашивает координаты через консоль (используя парсер из Спринта 9)
- [ ] В `Game.cs` — метод `Play()`, который:
  - у каждого игрока — своя расстановка (ручная или случайная)
  - в цикле чередует ходы: `player1.GetShot()` → стрельба по `player2.OwnBoard` → проверка победы → смена хода
  - между ходами — `Console.WriteLine("Передайте ход игроку 2, нажмите Enter"); Console.ReadLine();`
- [ ] Вывод: каждый видит своё поле (с кораблями) и поле противника (без кораблей, только попадания/промахи)

**Definition of Done:** два человека могут по очереди играть за одним компьютером от расстановки до победы одного из них.

**Это контрольная точка №3** — полноценная игра для двоих, без ИИ. Хорошее место сделать паузу и отпраздновать результат.

---

## Спринт 13. Компьютерный соперник — простой ИИ

**Цель:** заменить второго человека на компьютер.

**Задачи:**
- [ ] Создать `ComputerPlayer : Player`
- [ ] Переопределить `GetShot()`:
  - хранить `HashSet<(int,int)>` уже использованных координат
  - генерировать случайные `row`, `col`, пока не найдётся неиспользованная пара
- [ ] В `Game.Play()` дать выбор: играть против человека или против компьютера
- [ ] Добавить `Thread.Sleep(500)` перед ходом компьютера — чтобы не было мгновенного вывода (ощущается более "по-настоящему")

**Definition of Done:** можно играть против компьютера, который стреляет случайно, но никогда не повторяет клетку.

---

## Спринт 14. Компьютерный соперник — "умная охота" (опционально, продвинутый уровень)

**Цель:** после попадания компьютер должен целенаправленно добивать корабль.

**Задачи:**
- [ ] В `ComputerPlayer` добавить состояние: `Queue<(int,int)> targetQueue` — очередь клеток "на подозрении"
- [ ] Логика `GetShot()`:
  - если `targetQueue` не пуста — стрелять по клетке оттуда
  - иначе — стрелять случайно (как в Спринте 13)
- [ ] После попадания (не потопления) — добавить в очередь 4 соседние клетки (если они в границах и ещё не стреляны)
- [ ] После потопления корабля — очистить очередь (чтобы не продолжать "охоту" за уже мёртвым кораблём)

**Definition of Done:** после первого попадания компьютер явно начинает стрелять по соседним клеткам, а не в случайные места поля.

**Подводные камни:** легко забыть очистить очередь после потопления — тогда ИИ будет "путаться" между разными кораблями.

---

## Спринт 15 (опционально). Полировка и доп. фичи

Эти фичи не обязательны, но хороши для практики — можно выбирать любые, независимо друг от друга:

- [ ] Статистика партии: количество ходов, точность (% попаданий)
- [ ] Сохранение результатов в текстовый файл между запусками (топ игроков)
- [ ] Уровни сложности для ИИ (лёгкий = чисто случайный, сложный = "охота" из Спринта 14)
- [ ] Цветной вывод в консоль (`Console.ForegroundColor`) — попадания красным, промахи синим
- [ ] Возможность сохранить/загрузить игру в процессе (сериализация состояния поля в JSON)

## Карта концепций C# по спринтам

Что именно закрепляется на каждом этапе — полезно держать в голове, чтобы не просто "написать код по инструкции", а понимать, зачем каждый шаг.

| Спринт | Ключевая концепция | На что обратить внимание |
|---|---|---|
| 0 | Структура проекта | Разделение на файлы/папки — привычка, а не формальность |
| 1 | Двумерные массивы (`char[,]`) | Разница между `grid[row, col]` и координатами x/y — частая путаница |
| 1 | Вложенные циклы (`for` в `for`) | Порядок обхода: сначала строки, потом столбцы |
| 2 | Классы и конструкторы | Класс = данные + поведение вместе, а не просто "структура с числами" |
| 2 | Кортежи (`(int, int)`) и `List<T>` | Удобны для координат без создания отдельного класса `Point` |
| 3 | Инкапсуляция | Поля `Grid` и `Ships` управляются через методы `Board`, а не меняются напрямую снаружи |
| 3 | Композиция классов | `Board` содержит `List<Ship>` — объект внутри объекта, это не наследование |
| 4 | Работа с коллекциями (`List<T>`) | Добавление, перебор через `foreach`, а не только через индексы |
| 5 | Ввод/вывод, `Console.ReadLine()` | Разница между вводом как строкой и числом — `int.Parse`/`int.TryParse` |
| 5 | Циклы с условием выхода (`while(true)` + `break`) | Игровой цикл — этот паттерн встретится ещё много раз |
| 6 | `enum` | Именованные константы вместо "магических" символов типа `'H'`, `'M'` |
| 6 | Условные конструкции, `switch` | `switch` по `enum` — чище, чем цепочка `if-else` |
| 7 | Методы, возвращающие `bool` | `IsSunk()` — метод-предикат, инкапсулирует логику внутри класса, а не снаружи |
| 8 | Циклы с сложным условием выхода | `while (!AllShipsSunk())` — условие зависит от состояния объекта, а не от счётчика |
| 9 | Работа со строками (`string`) | `Substring`, индексация символов, `char.ToUpper()` |
| 9 | `out`-параметры и `TryParse`-паттерн | Стандартный C#-паттерн для "может не получиться" без исключений |
| 9 | Обработка ошибок ввода | Валидация — это не "лишний код", а часть логики метода |
| 10 | Более сложная логика метода (несколько условий) | `CanPlaceShip` — хороший пример метода с ранним выходом (`return false` при первом нарушении) |
| 10 | Булева логика (`&&`, `||`, `!`) | Комбинация условий границ + пересечений + соседства |
| 11 | Класс `Random` | Важно: создавать `Random` один раз (полем класса), а не в цикле — иначе будут повторяющиеся значения |
| 11 | Циклы с ограничением попыток | Защита от бесконечного цикла (`for (int attempt = 0; attempt < 100; attempt++)`) |
| 12 | Наследование (`: Player`) | `HumanPlayer` — это `Player`, но с другим поведением одного метода |
| 12 | Полиморфизм и `virtual`/`override` | Код игрового цикла не знает, человек ходит или нет — вызывает `player.GetShot()` одинаково для всех |
| 12 | Модификаторы доступа (`private`/`public`/`protected`) | Что должно быть видно снаружи класса, а что — только внутри |
| 13 | Полиморфизм (продолжение) | `ComputerPlayer` — второй наследник `Player`, тот же принцип, что и `HumanPlayer` |
| 13 | `HashSet<T>` | Эффективная проверка "уже стреляли сюда?" — быстрее, чем перебор `List` |
| 14 | `Queue<T>` | FIFO-логика — стрелять по клеткам в том порядке, в котором они попали в очередь |
| 14 | Управление состоянием объекта | ИИ должен "помнить" контекст между ходами — это уже близко к простому конечному автомату |
| 15 | Сериализация (JSON/файлы) | Отдельная большая тема — `System.Text.Json` или ручная запись в текстовый файл |

## Порядок важности, если время ограничено

Если нужно расставить приоритеты (например, готовитесь к экзамену или собеседованию), вот что просело бы больше всего, если пропустить:

1. **Классы, инкапсуляция, композиция** (Спринты 2-3) — без этого всё остальное развалится в кучу глобальных переменных
2. **Наследование и полиморфизм** (Спринт 12) — это то, ради чего вообще стоит доделывать проект до двух игроков, а не просто "поиграть самому"
3. **Коллекции** (`List`, `HashSet`, `Queue`) — используются повсеместно, без них большинство методов будет неудобно писать
4. **Валидация и обработка ошибок ввода** (Спринт 9) — часто недооценивают, но именно это отличает "учебный скрипт" от программы, которая не падает от неверного ввода

---

## Как пользоваться этим планом

1. Не начинать следующий спринт, пока не выполнены все пункты Definition of Done текущего
2. Каждый спринт — это отдельный коммит в git (если используется), с понятным сообщением ("Спринт 6: добавлена логика попаданий")
3. Если спринт кажется слишком большим — можно дробить его на подпункты и делать по одному в день
4. Спринты 13–14 (ИИ) можно отложить сколь угодно долго — игра для двух людей (после Спринта 12) уже полностью рабочая и играбельная
